---
name: Refined comparison briefs
description: How intake refinement should preserve user wording while constraining downstream research.
---

Keep the user’s original sentence as the displayed, persisted, and identity-bearing request. After parsing and deterministic validation, create a separate internal processing brief that carries the inferred market, explicit or assumed audience context, criteria, discovery requirements, and like-for-like constraints into research.

**Why:** Replacing the original request makes saved reports and audit trails misleading, while passing raw prose alone lets research reinterpret entity boundaries, demographics, or comparability after validation.

**How to apply:** Any submission path that invokes research must use the processing brief for analysis but use the original request for persistence, display, errors, idempotency, and comparison identity. Open-ended labels must be resolved into concrete local offerings before scoring.
